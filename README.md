# Tiny-CA

Running a [step-ca](https://github.com/smallstep/certificates) server with [pico-rng](https://github.com/polhenarejos/pico-rng) and [pico-hsm](https://github.com/polhenarejos/pico-hsm) on a Raspberry Pi Zero W

This project / guide is heavily inspired by [step-ca's tiny ca build](https://smallstep.com/blog/build-a-tiny-ca-with-raspberry-pi-yubikey/) ([archive.org link](https://web.archive.org/web/20260914210127/https://smallstep.com/blog/build-a-tiny-ca-with-raspberry-pi-yubikey/))

## Secrets

This project will create the following secrets:

### Offline / analog

**Never type these into a machine that you not trust, is air-gapped or could otherwise retain / distribute data you process on it!**

- Offline-CA luks2 password (generated for you)
- Root-CA key password (generated for you)
- hsm-pin (generated for you, used to login to the pico-hsm)
- hsm-so-pin (generated for you, used to recover the pico-hsm / set a new pin)

### Online / digital

**These are provided by the user and need to be entered to manage the CA. Use a password manager to generate & store these**

- Online-CA key password (generated by the user)
- Online-CA initial provisioner password (generated by the user)

## Requirements

### For the setup

- Machine with docker installed and buildx / qemu setup for the target architecture
- An internet connection
- Display & keyboard connected to the Pi to note down the luks2 password, hsm-PIN and SO-PIN & root-key during initial generation
- Raspberry Pi Pico / Pico 2 (skip the pico-rng step when using an ESP32-S3)
- An internet connection to the Pi
- (Recommended) An ssh connection to the Pi
- Micro USB (M) OTG to USB A (F) adapter
- (powered) USB hub (the Pico draws a lot of power when resetting, which can cause the hub, or even the Pico to brownout).
- Cable to connect the Pico to the USB hub

### For actual operation

- Raspberry Pi with latest OS (this assumes a Pi Zero W, but other SBCs also work with some changes)
- LAN connection to the Pi
- Raspberry Pi Pico / Pico 2 / ESP32-S3 compatible board
- Micro USB (M) OTG to USB A (F) adapter
- Cable to connect the Pico to the OTG adapter

## Steps

1. Compile step-ca (with `CGO` enabled) and pico-rng (comment out the last two `COPY` commands in [Dockerfile](./Dockerfile#L72) when using an ESP32-S3).

   This is done on a faster machine using armv6 emulation, because the Pi Zero is too slow to do this in a reasonable amount of time and can run out of RAM.

   This still takes > 30min on a AMD Ryzen 5 7500F with a 60 Mbit/s connection and 32GB of RAM.

   ```bash
   docker buildx build --cache-from=type=local,src=./docker-cache --cache-to=type=local,dest=./docker-cache --platform linux/arm/v6 -t tiny-ca:arm32v6 --load .
   # Go watch some anime i.g.

   docker create --name tiny-ca-temp --platform linux/arm/v6 tiny-ca:arm32v6 --
   for file in step-ca step-kms-plugin pico_rng.ko pico_rng.uf2; do
       docker cp tiny-ca-temp:/usr/local/app/out/$file bin
   done
   docker rm tiny-ca-temp
   ```

1. Copy files (`bin/`, `scripts/` and `templates/`) to the Pi & run the [pre-init.sh](scripts/pre-init.sh) script

   This will:
   1. Download & install required tools
   1. Disable auto-connect for the first active nmcli connection
   1. Enable the read-only filesystem
   1. Reboot

1. Now log back in (with a screen & keyboard) & run the [init.sh](scripts/init.sh) script

   This will:
   1. Flash pico-rand & load driver
   1. Generate all required passwords
   1. Create luks2 fs on the connected offline-storage device (by UUID)
   1. Create the root CA on it
   1. Flash and setup pico-hsm
   1. Sign the intermediate key with a key on the pico-hsm
   1. Enable auto-connect for the previously active nmcli connection
   1. Enable r/w filesystem
   1. Display all passwords & wait until user confirms they wrote them down
   1. Reboot

1. Now log back in again (this step should be done over ssh) & run the [post-init.sh](scripts/post-init.sh)script

   This will:
   1. Create the actual step-ca environment
   1. enable the step-ca service

Now you can import your root.crt from the 2nd USB storage device on all of your devices
